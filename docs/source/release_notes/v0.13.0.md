# v0.13.0

## Highlights

### New modules for LC system characterization and instrument control

- `CADETProcess.instruments` — declarative LC protocol API for instrument control
- `CADETProcess.calibration` — signal preprocessing and peak detection for reference IO
- `CADETProcess.characterization` — LC system parameter fitting (Van Deemter, Yamamoto, pore/film diffusion)

### Docs: reference section rebuilt ([#386](https://github.com/fau-advanced-separations/CADET-Process/pull/386))

The autosummary template was generating one page per class member, producing ~3200 files and making the reference section unusable.
Switching to `autoclass :members:` with `numpydoc_show_class_members = False` reduces the output to ~370 pages, with all member docs rendered inline on the class page.

### Fractionation improvements ([#387](https://github.com/fau-advanced-separations/CADET-Process/pull/387))

- `Fractionator` and `FractionationOptimizer` decoupled from `SimulationResults`: both now accept `(chromatograms, process_meta)` directly.
  Passing `SimulationResults` still works with a `DeprecationWarning`.
  `optimize_fractionation` also gains a `c_min` keyword to set the minimum total concentration below which purity is considered undefined, overriding each chromatogram's default per call (closes #56).

### Optimization infrastructure refactor ([#388](https://github.com/fau-advanced-separations/CADET-Process/pull/388))

`OptimizationProblem` internals have been restructured into two focused modules.
`ParameterSpace` owns parameter declarations, bounds, normalization, linear constraints, and dependency resolution.
`EvaluationPipeline` makes the evaluation graph explicit: evaluators, objectives, and constraints are DAG nodes connected by named outputs, so all objectives sharing a simulation get it structurally rather than by cache accident.

The public API of `OptimizationProblem` is largely unchanged; some internal properties used by optimizer adapters were removed.
The `diskcache` dependency is replaced by pipefunc's built-in cache backends; pass `cache_directory` to persist results to disk as before.

`add_variable` now accepts `parameter_type=int` for integer variables, and a new `add_choice_variable` method registers categorical variables with a finite set of allowed values.
Optimizers declare support via `supports_integer_variables` and `supports_categorical_variables` flags (default False); `check_optimization_problem` rejects problems with unsupported variable types before the run starts.

### Jacobian methods support caller-specified evaluation space

`OptimizationProblem.objective_jacobian` and `nonlinear_constraint_jacobian` accept `untransform`, `get_dependent_values`, and `ensure_minimization` as explicit keyword arguments, forwarded through `approximate_jac` so that perturbation and function evaluation occur in the same space.
`approximate_jac` also gains a backward-difference fallback for points where a forward step would exceed bounds.


### IPOPT optimizer ([#111](https://github.com/fau-advanced-separations/CADET-Process/pull/111))

IPOPT is now available via `CADETProcess.optimization.IPOPT`.
The adapter is built on `cyipopt.Problem`, which provides a per-iteration `intermediate()` hook for live progress reporting and checkpointing, matching the behavior of the other adapters.
Gradients and constraint Jacobians are supplied analytically in transformed space via `objective_jacobian` and `nonlinear_constraint_jacobian`.

## Deprecations

### Comparator API ([#102](https://github.com/fau-advanced-separations/CADET-Process/pull/102))

`Comparator.add_difference_metric` now accepts a pre-constructed `DifferenceBase` instance as its primary argument:

```python
metric = SSE(reference)
comparator.add_difference_metric(metric, 'outlet.outlet')
```

The old string-based factory form and `add_reference` still work but emit a `DeprecationWarning`.
Both will be removed in v1.0.
The new API decouples metric construction from registration: users configure metrics directly,
and the Comparator no longer needs to hold a reference registry.
