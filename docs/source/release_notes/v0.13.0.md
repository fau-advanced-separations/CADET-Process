# v0.13.0

## Highlights

### New modules for LC system characterization and instrument control

- `CADETProcess.instruments` — declarative LC protocol API for instrument control
- `CADETProcess.calibration` — signal preprocessing and peak detection for reference IO
- `CADETProcess.characterization` — LC system parameter fitting (Van Deemter, Yamamoto, pore/film diffusion)

### Docs: reference section rebuilt ([#386](https://github.com/fau-advanced-separations/CADET-Process/pull/386))

The autosummary template was generating one page per class member, producing ~3200 files and making the reference section unusable.
Switching to `autoclass :members:` with `numpydoc_show_class_members = False` reduces the output to ~370 pages, with all member docs rendered inline on the class page.

### Fractionation improvements ([#387](https://github.com/fau-advanced-separations/CADET-Process/pull/387))

- `Fractionator` and `FractionationOptimizer` decoupled from `SimulationResults`: both now accept `(chromatograms, process_meta)` directly.
  Passing `SimulationResults` still works with a `DeprecationWarning`.
  `optimize_fractionation` also gains a `c_min` keyword to set the minimum total concentration below which purity is considered undefined, overriding each chromatogram's default per call (closes #56).

### Optimization infrastructure refactor ([#388](https://github.com/fau-advanced-separations/CADET-Process/pull/388))

`OptimizationProblem` internals have been restructured into two focused modules.
`ParameterSpace` owns parameter declarations, bounds, normalization, linear constraints, and dependency resolution.
`EvaluationPipeline` makes the evaluation graph explicit: evaluators, objectives, and constraints are DAG nodes connected by named outputs, so all objectives sharing a simulation get it structurally rather than by cache accident.

The public API of `OptimizationProblem` is largely unchanged; some internal properties used by optimizer adapters were removed.
The `diskcache` dependency is replaced by pipefunc's built-in cache backends; pass `cache_directory` to persist results to disk as before.

`add_variable` now accepts `parameter_type=int` for integer variables, and a new `add_choice_variable` method registers categorical variables with a finite set of allowed values.
Optimizers declare support via `supports_integer_variables` and `supports_categorical_variables` flags (default False); `check_optimization_problem` rejects problems with unsupported variable types before the run starts.

### Sampler abstraction ([#405](https://github.com/fau-advanced-separations/CADET-Process/pull/405))

Sampling strategies are now pluggable.
`SamplerBase` owns the feasibility contract; concrete backends supply candidates.
`HopsySampler` (uniform polytope sampling, the default) is joined by `LatinHypercubeSampler` and `SobolSampler`, which produce space-filling designs for box-bounded problems, e.g. surrogate training data, and can be passed to `create_initial_values` via the new `sampler` argument.
Sampled values carry proper types: `int` for integer variables, declared values for categorical ones.
`get_chebyshev_center` now verifies the returned point against linear constraints referencing dependent variables and raises rather than returning an infeasible point.
Optimizers declare `supports_unbounded_parameters` (default False); unbounded problems are rejected up front for optimizers that need a sampled initial population.
A new user guide page, Parameter Spaces and Sampling, covers standalone usage.

### Jacobian methods support caller-specified evaluation space

`OptimizationProblem.objective_jacobian` and `nonlinear_constraint_jacobian` accept `untransform`, `get_dependent_values`, and `ensure_minimization` as explicit keyword arguments, forwarded through `approximate_jac` so that perturbation and function evaluation occur in the same space.
`approximate_jac` also gains a backward-difference fallback for points where a forward step would exceed bounds.


### IPOPT optimizer ([#111](https://github.com/fau-advanced-separations/CADET-Process/pull/111))

IPOPT is now available via `CADETProcess.optimization.IPOPT`.
The adapter is built on `cyipopt.Problem`, which provides a per-iteration `intermediate()` hook for live progress reporting and checkpointing, matching the behavior of the other adapters.
Gradients and constraint Jacobians are supplied analytically in transformed space via `objective_jacobian` and `nonlinear_constraint_jacobian`.

### `MetricSpace` and `Problem`

The output side of an optimization problem now has the same kind of dedicated infrastructure the input side has had since `ParameterSpace`: `Metric` declares a named output and its shape; `MetricSpace` collects metrics and annotates them with direction, constraint bounds, and normalization, mirroring `ParameterSpace`.
`Problem` (`ParameterSpace` + `MetricSpace` + an `EvaluationBackend`) is a general, optimizer-independent problem description; `OptimizationProblem` is now a `Problem` subclass that adds objective/constraint policy on top.
`problem.with_evaluator(surrogate)` swaps in a different backend (e.g. a surrogate model) without mutating the original, returning a plain `Problem` usable by samplers and surrogates directly, with no optimizer attached.

`OptimizationProblem`'s public API (`add_objective`, `add_nonlinear_constraint`, `objective_labels`, ...) is unchanged, with two behavior fixes: objective and constraint names now share one namespace and registering a duplicate raises instead of only warning, and label expansion for a metric that spans multiple evaluation objects is now object-major, matching the order values are actually returned in (previously the two orders disagreed whenever a metric had more than one entry and more than one evaluation object, silently mislabeling columns).

### Columnar `Population` storage

`Population` now stores parameters and metrics as named columns (`pop.X["flow_rate"]`, `pop.metrics["yield"]`) instead of fixed `f`/`g`/`cv`/`m` arrays per individual.
Named columns can hold categorical values, which a float matrix cannot; this was the blocker for end-to-end optimization over categorical variables.
Everything previously stored per row is now derived from the columns and the attached spaces: objective matrices (`pop.f`, `pop.f_minimized`) read direction annotations from `MetricSpace`, constraint violations (`pop.cv_nonlincon`, `pop.cv_bounds`, `pop.cv_lincon`) are computed from stored values and bounds, and feasibility and dominance are population-level operations.
Storing only ground truth eliminates the class of bugs where a stored derived value (per-individual `f_minimized`, label lists, feasibility flags) went stale or disagreed with the global annotation it duplicated.

**Breaking changes:**

- `Individual` is removed.
  Indexing a population with a scalar returns an `IndividualView`, a read-only row lens: `pop[0].X["flow_rate"]`, `pop[0].metrics["yield"]`.
  Slices, index lists, and boolean masks return a new `Population`.
  Callbacks that request the `individual` argument receive an `IndividualView`; `individual.x`/`individual.f` become `individual.X`/`individual.metrics`.
- `Population` is immutable: `add_individual`/`remove_individual`/`update` are gone.
  One-row populations are created with `Population.from_sample(...)` or `view.as_population()`; combination is explicit via `Population.concat([p1, p2])`.
  Construction requires a `MetricSpace` (and, for parameter-side violations, a `ParameterSpace`); `OptimizationProblem.create_population` wires both.
- `create_individual` is removed; use `create_population` with a single row.
- Meta scores are now ordinary metrics without direction annotation on `MetricSpace`; `m`/`m_minimized` storage disappears.
  `add_meta_score` gains the same `name`/`evaluation_objects`/`requires` wiring as `add_objective`, and meta-score names share the single metric namespace.
- Row identity by UUID/hash is gone; deduplication and lookups (`pop.index_of`, `x in pop`) use exact value matching on the parameter columns.
- Optimization checkpoints (`checkpoint.h5`) written by earlier versions cannot be loaded; the serialized format now stores named columns plus a metric-space spec, making checkpoints self-describing.

## Deprecations

### Comparator API ([#102](https://github.com/fau-advanced-separations/CADET-Process/pull/102))

`Comparator.add_difference_metric` now accepts a pre-constructed `DifferenceBase` instance as its primary argument:

```python
metric = SSE(reference)
comparator.add_difference_metric(metric, 'outlet.outlet')
```

The old string-based factory form and `add_reference` still work but emit a `DeprecationWarning`.
Both will be removed in v1.0.
The new API decouples metric construction from registration: users configure metrics directly,
and the Comparator no longer needs to hold a reference registry.

## Other changes

- Fix `EvaluationFailure` cache policy: an unclassified exception now defaults to `recoverable=True` and is never cached, so a transient failure (OOM, cluster hiccup) can no longer permanently poison a legitimately good x. Deterministic failures (solver divergence, validation rejection) are still cached; a node author classifies one explicitly by setting `recoverable = False` on the raised exception.
- Fix `add_variable(..., indices=0)` on a polynomial parameter (e.g. a single-component entry of a multi-component concentration profile): a bare index selecting a whole coefficient row silently broadcast the scalar across every coefficient instead of setting just the constant term and zeroing the rest, the convention the no-index case already gets for free
- Fix checkpoint restore in the pymoo and Ax adapters: restored populations are now fed to the optimizer in its own coordinate system (transformed independent coordinates, minimized objectives, constraint violations) instead of full physical vectors, which broke resuming whenever normalization or dependent variables were active
- Fix `StopIteration` in purity plots when the number of components exceeds the color cycle length (e.g. GIEX with a pH tracer) ([#401](https://github.com/fau-advanced-separations/CADET-Process/pull/401))
- Fractionation optimizer test suite added: synthetic chromatogram fixtures cover eight separation regimes plus infeasibility, recovery monotonicity, and multi-outlet fractionation; no CADET-Core required ([#279](https://github.com/fau-advanced-separations/CADET-Process/pull/279))
- Test suite restructured to mirror package layout; shared fixtures moved to `conftest.py` ([#378](https://github.com/fau-advanced-separations/CADET-Process/pull/378), [#379](https://github.com/fau-advanced-separations/CADET-Process/pull/379))
- Coverage baseline established at 73% (2026-05-16)
- Docs CI check added (`.github/workflows/docs.yml`); runs on all PRs with `nb_execution_mode=off`
- Fix leaked worker processes after optimization: parallelization backends now release their worker pool at the end of `optimize()`, so a run no longer hangs at interpreter exit (Pathos) or stalls on loky's idle timeout (Joblib) ([#408](https://github.com/fau-advanced-separations/CADET-Process/pull/408))
